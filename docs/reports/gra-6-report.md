## What

The schema of GRA-1's "Tenancy and the schema", in Drizzle over Postgres, with one migration that applies to an empty database and the services above it in Cando's shape (ADR 0011): injected dependencies, runnable without a database, `packages/core/src/agent/agent.service.test.ts` the reference.

**`@graft/db`** — twelve owned tables (`agent`, `agent_connection`, `connection`, `authored_tool`, `tool_version`, `working_set`, `working_set_change`, `approval`, `build_approval`, `pending_action`, `acquire_job`, `usage_ledger`) plus Better Auth's four, every owned one carrying `owner in ('person','org') default 'person'` (ADR 0007) and `created_at`, the mutable ones `updated_at`. Every foreign key indexed, plus `(agent_id, last_used_at)` for the sweep. Repositories under `src/repo/*` take the scope **in the SQL**: agent-scoped tables carry `agent_id` alone, so every such statement goes through `scopedAgentIds` — `agent_id IN (select id from agent where id = $agent and person_id = $person)` — and a mis-scoped call matches nothing. Cando's `migration-chain.ts` arrives as `db:check-chain`; `drizzle/0000_persons_agents_connections_toolbox.sql` is the chain's first link. Root `docker-compose.yml` (postgres:18, `GRAFT_POSTGRES_PORT` overridable) and `db:*` scripts as `-F @graft/db` filters.

**`@graft/auth`** — `createAuth({ db, secret, baseURL, trustedOrigins })`: email and password, verification **off for the alpha** (the reason is on the option: no mail transport exists yet and the self-hosted image bootstraps its admin from the environment), no social provider, no organization plugin. Its four tables are generated by `pnpm --filter @graft/auth generate-schema` (the CLI via `pnpm dlx`, so `@prisma/client` and `better-sqlite3` stay out of the lockfile).

**`@graft/core`** — `requirePerson(session)`, `requireAgent(ctx, token, deps)` (SHA-256 of the bearer, revoked refused in the statement), `mintAgentToken`; agent, connection, tool, working-set, approval, pending-action, acquire-job and ledger services; `approvalDecision({ annotations, approval })` as ADR 0008 in one pure function; `toProxyConnection` for the proxy's binding. `ServiceError` with a code the transport maps.

**`@graft/env`** — `GRAFT_DATABASE_URL`, `GRAFT_AUTH_SECRET` (32+), `GRAFT_AUTH_URL` (http(s) origin) required; `GRAFT_CORS_ORIGIN` an optional list parsed to `string[]`, each entry held to be an origin.

**`@graft/server`** — `createDb(env.GRAFT_DATABASE_URL)`, Better Auth at `/api/auth/*`, a plain Hono JSON API for agents and connections at `/api/*` (mounted after the proxy, with CORS only on it), the proxy's connection source switched to the database through the same `ProxyDeps["connections"]` seam, `GRAFT_DEV_SEED` layered over it. Decrypt stays in exactly one place: `app.ts`'s proxy binding; the connection service takes `EncryptOnlyVault`.

## Decisions

- **Better Auth 1.7.2's `account` needs `issuer`, and the newest published `@better-auth/cli` (1.4.21) predates it.** The column and the `(issuer, account_id)` unique index are added by hand; the generated file's header says so and says to re-add them after any regeneration. The integration suite signs a person up against the migrated schema, which is what catches a regeneration that drops them.
- **Agent-scoped tables carry `agent_id` alone, not a denormalised `person_id`.** The scope still enters every statement, through the `scopedAgentIds` subquery; `packages/db/src/repo/scope.test.ts` pins that predicate on every agent-scoped read and write.
- **Append-only records (`tool_version`, `working_set_change`, `usage_ledger`, `agent_connection`, `build_approval`) have no `updated_at`** — a column nothing maintains is a claim the next reader trusts. `working_set_change`'s moment is `created_at`.
- **Revoking a connection deletes approvals for every tool of the vendor, for every agent** (ADR 0007), and build approvals for the connection; it clears the credential, the OAuth client secret and the refresh state, stamps `revoked_at`, and leaves the row and the tools. Re-entering a credential clears `revoked_at`: that is the reconnection.
- **Promotion never refuses on the cap**; ADR 0009's rule is a backstop that demotes (GRA-24). `promoteTool` answers `{ changed }` so the caller decides whether to fire `tools/list_changed`.
- **The integration suite creates a throwaway database per run** on the server `TEST_DATABASE_URL` names, so "applies to an empty Postgres" is literal and nothing leaks into a developer's database. Skips without the variable; refuses to skip under `CI`.
- **The pending-action refusals are in the statement** — answering requires unanswered and unexpired, consuming requires answered and unconsumed — and the service reads the row back only to say *which* (`GONE`, `CONFLICT`, `NOT_FOUND`).
- **Catalog additions:** `drizzle-orm ^0.45.2`, `drizzle-kit ^0.31.10`, `pg ^8.23.0`, `@types/pg ^8.23.1`, `better-auth 1.7.2`, `dotenv ^17.4.2`.

How `apps/server/src/index.ts` constructs deps:
```ts
const vault = createCredentialVault(createLocalKeyring(env.GRAFT_KEYRING_SECRET));
const db = createDb(env.GRAFT_DATABASE_URL);                       // db.close() on SIGINT/SIGTERM
const auth = createAuth({ db, secret: env.GRAFT_AUTH_SECRET, baseURL: env.GRAFT_AUTH_URL, trustedOrigins: env.GRAFT_CORS_ORIGIN });
createServer({ keys, vault, followRedirects: env.GRAFT_PROXY_FOLLOW_REDIRECTS,
  connections: createDatabaseConnections(db),                      // layered under GRAFT_DEV_SEED when set
  api: { auth: { handler: (req) => auth.handler(req), getSession: (headers) => auth.api.getSession({ headers }) },
         deps: { db, agent: defaultAgentDeps, connection: createConnectionDeps({ encrypt: vault.encrypt }) }, corsOrigins: env.GRAFT_CORS_ORIGIN } });
```
