**Plugin choice.** Not Better Auth. The ticket's "MCP plugin over the OIDC provider" is `@better-auth/mcp` over `@better-auth/oauth-provider` in 1.7 (the OIDC plugin no longer exists; 1.7.2 ships neither in `dist/plugins`). I read both 1.7.2 tarballs. Rejected on five counts recorded in **ADR 0018**: its token subject is the *person*; eight tables (one of ~40 columns) the pinned `@better-auth/cli@1.4.21` predates; issuer at `…/api/auth`; ~320 KB minified with DPoP/logout/introspection/CIMD we do not need; and a JWT access token that cannot be revoked before expiry. Graft is its own authorization server: `packages/core/src/mcp-oauth/` (rules, service, sealed replay) and `apps/server/src/mcp-oauth.ts`.

**Token design.** Opaque tokens hashed at rest in one `mcp_token` table, **subject = agent**; `grft_` (static) and `grfta_` (OAuth access) both resolve through `requireAgent` by prefix. Access tokens 1 h; refresh tokens live with the agent; every resolving read joins `agent.revoked_at IS NULL`, and revoking the agent stamps the token rows in the same transaction. Rotation: guarded claim + pair + seal in one transaction, one successor per predecessor; a retired token presented again within 30 s is answered **the same pair**, opened from an AES-256-GCM seal keyed by HKDF over the retired token itself (DB alone cannot open it); past 30 s it is a replay that revokes the grant. Code exchange: consume + issue atomic, a lost race revokes the winner's tokens; a code whose agent was revoked since consent is refused. `agent.token_hash`/`token_prefix` nullable; `connected_via_client_id`/`_name` added. Migration **0005_mcp_oauth**; chain continuous.

**No new environment variable.** Issuer = `GRAFT_AUTH_URL` origin; consent page under `GRAFT_CONSOLE_URL`. Cloud's task definition is unchanged.

**Endpoints.** `/mcp` 401 → `WWW-Authenticate: Bearer resource_metadata="<origin>/.well-known/oauth-protected-resource/mcp"` (`error="invalid_token"` when a token was presented). `GET /.well-known/oauth-protected-resource` (both RFC 9728 forms) and `/.well-known/oauth-authorization-server` at the origin root, above the SPA fallback. `POST /mcp/oauth/register` (RFC 7591, unauthenticated, bounded 16 KB / 10 URIs of 2 KB), `GET /mcp/oauth/authorize` (→ console `/consent`, or an error redirect for the client's own parameter mistakes; never a redirect to an unregistered URI), `POST /mcp/oauth/token` (code+PKCE S256 required, RFC 8707 `resource`, refresh), `POST /mcp/oauth/revoke` (RFC 7009) — all CORS-open, outside `/api`. Console: `GET /api/mcp-oauth/request`, `POST /api/mcp-oauth/consent` with the session.
